- Six old position127 command captures provide L0/8/16/24/31 Attention inputs and full outputs, L0 MLP input and full output, plus five 8 MiB `kv_before` layers. The captured `kv_before` position127 records were stale physical bytes and are not committed history. Only positions0..126 are compared to current DDR as old historical references.
- The released [`scalellm_decode16.py`](../DOWNLOADS.md#archive-files) stores each KV record as 32 signed 12-bit values, scale metadata and reserved padding. DDR records carry no valid, layer, slot, position or epoch tag. Addresses select layer/slot/position; request epoch/length are command and scratch state. A read-only scan can prove record-format integrity and historical byte identity for five captured layers, but cannot prove the original provenance of the other 27 layers from bytes alone.
- The first complete replay at position127 must reproduce all 16 old token IDs and six selected A/M inputs and outputs byte for byte. This supplies a same-implementation consistency check for the 27 layers through the complete model path, not an independent model oracle. A failure stops the current-state route; a controlled fresh 0..126 warmup is then required. The old 128-step model window was 9843.49 s, so a full warmup route has an approximately 2 h 44 min observed upper planning cost before repetitions.

## Host sequence

`tools/power/kv128_sevenrail_workload.py verify-source` checks the old receipt, request SHA, 128-step/8192-command run, 16 checkpoint slot histories, last ACKed command descriptor, and all six sealed capture file hashes without opening XDMA.

`inspect-live` first verifies the bitstream file SHA256 `96df1a5c1bf4174921bc02ccd88df4066dece3d62b491acb3106bb90ac0ffc85`. It opens XDMA under the external exclusive lease, reads the published hardware identity and quiescent CSR, and requires ACK_ID=8192, retained completion descriptor equal to the old last command, and matching DONE_CYCLES. It then reads the entire 256 MiB KV allocation, verifies every 64-byte record's scale/padding/numeric encoding and nonzero historical scale in each layer/slot, compares five captured layers' 16×127 position history byte for byte, and writes the 32-layer snapshot and per-layer hashes. No DDR or CSR writes occur in this mode. OS boot continuity needs separate event-chain evidence from the board controller; WMI boot time alone may vary by about three seconds and is not used as an exact-match gate.

`run` accepts the inspected snapshot, rechecks current board CSR and all 256 MiB against that snapshot before any board write, loads the original resident weights with readback, and makes one unmeasured complete position127 step. The runtime slots are reconstructed from the old checkpoint and fixed requests with epoch1, position127, 16 active slots, original prompts and generated tokens, and length budget `129 - prompt_length`. Command IDs and buffer generations advance from the old last command 8192. The original host model adapter performs embedding, normalization, residuals, Host Down and LM-head. No single-layer command is counted as a full step. Before formal Attention windows, each of the five target layers undergoes an unmeasured full 8 MiB pre-append restore/readback and an equivalent local 16×4 KiB restore/readback, with full output and post-command layer bytes compared. Only after those five equivalence checks does the short local restore enter formal windows.

The controlled `--resume-command-trace` route now accepts only the two evidenced failed qualification prefixes: main_001's 43 continuous START/BUSY/DONE/ACK records through command8235, then main_003's 50 continuous records through command8285. It checks their launcher receipts, workload reports, completed-command summaries, exact frozen source hashes, the known heartbeat failure before any measured window, same inspected snapshot and QPC/OS session, matching old captured numerical bytes where available, and main_003's recorded main_001 resume lineage. The next board access first checks quiescent CSR ACK_ID=8285, retained descriptor/DONE bytes/cycles equal that last trace, and every byte of the 256 MiB snapshot. It issues no board write if any check fails. Once accepted, command IDs and buffer generations continue from 8285 and a fresh complete position127 qualification starts from the reconstructed 16-slot state. The corrected sampler heartbeat reads the most recent complete, same-run bus/sweep record from at most 32 KiB of telemetry tail and compares its QPC tick with the current QPC tick; it requires a measured age from zero to ten seconds and saves both ticks and the age for diagnosis. A concurrently incomplete final JSON line is skipped; file modification time is no longer used.

Each complete step restores only physical position127 of all 32×16 KV layer/slot spans from the accepted snapshot and readbacks those writes. Positions0..126 remain unchanged. The runtime then runs all 64 A/M commands and commits 16 tokens. Its exact measurement window starts immediately before `runtime.step()` enters embedding and ends only after `runtime.step()` returns after Host Down, LM-head and atomic commit. The full 256 MiB KV is compared to the snapshot after each step. Ten seconds of sampler activity immediately precede and follow each measured full step outside its window.

For repeated Attention, each window cycles layers 0, 8, 16, 24, 31 in fixed order and stops only after a whole five-layer cycle. Each command restores that layer's position127 physical records from its old captured pre-append bytes, uses its old captured 16-row input, the exact old position127 RoPE rows and the original resident attention weights, and compares its entire output before ACK. The window includes the restore, layer switching, host transfer and ACK intervals. It is labeled `attention_repeat` with per-layer command counts and FPGA cycles; it is not a 32-layer mean or continuous FPGA-only utilization.

For repeated MLP, each window uses the old captured L0 input and full-output byte comparison. The original L0 GU weights are staged and read back before the window; the repeated command and ACK intervals are inside. It is labeled `mlp_repeat`. Idle windows keep the board quiescent. All A/M/idle windows last at least 120 s, need at least 200 complete V/I rail points for each of the seven rails, and stop at a safe ACK boundary by the 180 s guard. Each full-step window also needs at least 200 points per rail. There are three windows for each of `idle`, `attention_repeat`, `mlp_repeat`, and `full_kv128_step`, fixed before observing power as blocks `idle→A→M→full`, `idle→M→full→A`, `idle→full→A→M`. The PMBus sampler is a separate read-only process; its clock shares the Windows QPC domain with the workload window markers. A single-run phase JSON supplies optional per-sweep labels; QPC windows remain authoritative.

The controller retains the exclusive board lease, enforces CPU 0–7, 8 GiB process RSS, at least 2 GiB free memory, wall time and safe stop rules, and records board boot-event continuity. The host script also caps itself to the allowed CPUs 0–7, one numerical thread, 8 GiB RSS and a 2 GiB memory floor. The old read-only `command_active_inference.py` wrapper supplies per-command QPC `commands.jsonl` with START, STATUS, DONE, transfer and ACK timestamps; `xdma.jsonl` alone cannot support BUSY-time analysis. The workload writes raw `inspection.json`/`kv_snapshot.bin` and later `workload.json`, `windows.jsonl`, `events.jsonl`, `xdma.jsonl`, `commands_summary.jsonl`; these are evidence from actual runs only. In main_004, all 12 windows and three full steps completed with 16 matching emitted tokens, six old capture comparisons and the full KV snapshot check. Three Attention windows completed 1,175/1,160/1,165 commands in balanced five-layer cycles; three L0 MLP windows completed 1,788/1,770/1,805 commands. All idle/A/M windows lasted at least 120 seconds; every seven-rail window had at least 456 complete V/I points on its least-covered rail. Across 9,129 command traces, only command14365 (L31 Attention, repeat2) lacked an observed BUSY sample: its first STATUS read came 94.51 ms after START, while DONE_CYCLES corresponds to 45.02 ms at 80 MHz, so that command's conservative BUSY inner interval is unknown. Its DONE, output validation and ACK remain recorded; the original launcher FAIL is preserved, and no BUSY interval is invented.
