# R012 generation protocol

Mission M005 / SM024. Authorization is the current controller's explicit full response-quality extension; earlier numerical-only windows do not cap this experiment. Implementation owner is A020 (`collaboration:/root/response_quality_generation`). Other workers own benchmark input/assessment and Root owns the contract/final report. Production files, old project, and old frozen sources remain read-only.

Both arms use the checked 32-layer Llama-3.1-8B-Instruct model, original dynamic activation/weight/KV12 quantizers, Group32 Hadamard, format05 Down S32/shift12/S45/S54, original LUTs and host FP32 residual/RMSNorm/shared unquantized FP32 LM head. CURRENT calls existing production functions. OUTPUT_ONLY uses the existing `arithmetic_context(v5, OUTPUT_ONLY)` replacements for Linear/RoPE/QK/Softmax/PV. It retains base quantization, clipping and common node exits. It is not an unquantized model.

The isolated cached adapter stores the exact `KV12(values_s12,codes_u8,shifts_u8)` objects along token dimension 1, one cache per layer/arm/turn. Dynamic activation and KV quantization reduce only the innermost 32 lanes, never across token rows. Append operation preserves each old token. Absolute position IDs are contiguous. Queries attend to all earlier/current keys using an absolute causal mask. Batch is one, unpadded; external attention masks/caches are rejected. Prefill chunks have at most 128 queries to bound quadratic PV temporary storage. HF layer/residual/norm order is preserved; unused HF floating RoPE is bypassed. The production source is unchanged.

Extended RoPE repeats production float64 position*`llama3_inv_freq` and `numpy_round_away` Q16 conversion for the configured number of positions. Every original 0..127 entry must be bitwise equal. Long context is experimental software only, not a hardware ABI claim. CLI upper bound 32768 is an arithmetic bound; Root freezes the actual context after benchmark token preflight and resource qualification. Pilot proposal: 2048 context, 512 new tokens. For up to 32768 keys, PV integer product <2^35 and current sum <2^50; exact common32 residual sum <2^47. QK scaling is independent of total key count and below 2^60 per group. Softmax LUT maximum is 65536: current row sum <=2^31 and reference interpolation-scaled row sum <=2^41. These fit int64. This does not establish memory feasibility at 32768; 128-query PV temporaries at that length can exceed the admitted budget.

CPU qualification checks independent free prefixes, EOS/eot, equal fixed token caps, prompt IDs/hashes, token-local activation/KV quantization, and 2048-position RoPE first128 equality without CUDA initialization. GPU qualification precedes every generation run. In both arms it compares native17 vs adapter no-cache17 and cached16+1, then extended no-cache130/512 against cached final-token execution. All 32 decoder last-token hidden vectors, final norm and full-vocabulary FP32 logits must be bitwise equal. Failure stops before quality generation. Qualification fixtures repeat pilot input IDs solely to exercise tensor geometry and are never assessed as benchmark answers.

Generation is greedy full-vocabulary argmax with smallest-ID tie breaking. Checkpoint native chat template uses `add_generation_prompt=True`; rendering is tokenized with `add_special_tokens=False` to avoid duplicate BOS. First-turn prompt token IDs must match between arms. Each arm freely generates its own continuation; divergence never forces shared prefixes. MT two-turn histories contain that arm's actual first answer. Native eos IDs, `<|eot_id|>` and `<|end_of_text|>` terminate immediately; raw IDs retain the stop token. Each arm has the same configured new-token cap. Inputs/answers are never silently truncated or padded; insufficient context fails. A capped response remains recorded as truncated, and cannot establish complete-answer preservation.

Evidence: streamed checkpoint tensor source hashes, loaded selected-byte checks, full quantized buffer hashes, shared head source hash, LUT/RoPE hashes, tokenizer/config/index identities, consumed code before/after, per-token raw IDs and timing, complete rendered prompt IDs/hashes, complete response text, stop reason/cap, per-arm audits, per-item first divergence, and actual resource peaks. Resource supervisor and GPU admission belong to Root. No GPU1 access or external-process control is allowed. Speed is a cost estimate of this experimental software, not FPGA implementation timing.
