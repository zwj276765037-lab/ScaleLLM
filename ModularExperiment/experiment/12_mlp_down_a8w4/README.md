# MLP Down A8W4 projection

## Scope and fairness boundary

- Production ScaleCode anchors: `hap_a8w4_group32_pack2_s17`,
  `hap_a8w4_scalecode_recover2_lut`, the two 8-row/12-column Down slices, and
  `hap_mlp_down_group_major_accum_s45`.
- Physical geometry: `16 rows x 12 columns`; 342 physical tiles cover the
  4,096 Down outputs, with mask `0x00f` on the final tile.
- Reduction geometry: each tile is accumulated over 448 SwiGLU group32 inputs,
  so a full pass contains 153,216 group-major transactions.
- Common input boundary: identical S9 activation vectors and S4 weight vectors
  plus each format's native scale metadata.
- Common output boundary: one S24 Q8.16 `16 x 12` tile record, identical tile
  ordering and tail mask.
- Matched throughput rule: every complete core must accept one group-major
  transaction per cycle and emit each of the 342 completed tile records.  No
  leaf-area multiplication is allowed in the formal resource table.

The fixed implementation target is `xcvu9p-flga2104-2L-e`, Vivado 2025.2,
100 MHz, `HD.CLK_SRC=BUFGCE_X0Y0`, 0.150 ns setup uncertainty, and zero hold
uncertainty.

## Compared implementations

### ScaleCode

`m12_sc_down_group_major` wraps the full production dual-slice arithmetic and
adds only ordering/protocol telemetry.  Every group contribution uses packed
integer dot products, integer ScaleCode multiplication and shift alignment.
Each of the 192 logical output lanes owns a 342-entry S45 tile-state bank.  The
last group is rounded from Q24 to Q16 and saturated once at the common S24
output.

### FP16 and FP32

`m12_fp_down_group_major` retains the same packed two-column integer dot
producer.  It applies activation and weight scales in floating point and keeps
one FP32 state bank/add path per output lane and tile:

- FP16: S17-to-FP32-to-FP16 conversion, activation-scale and weight-scale
  FP16 multiplies, then FP16-to-FP32 conversion, FP32 tile state/add, and
  FP32-to-S24 final conversion.
- FP32: S17 to FP32, two FP32 multiplies, FP32 tile state/add and FP32-to-S24.

The 342-tile interleave is longer than the FP32 state read/modify/write
latency, so both FP cores can accept one transaction/cycle without duplicating
the complete Down engine.  This is a native boundary-inclusive baseline: FP
does not receive a free pre-scaled contribution and does not consume a value
first reconstructed by ScaleCode.

## Ordering and protocol

The full workload is group-major:

```text
for group in 0..447:
  for tile in 0..341:
    send(group, tile)
```

`in_first_group` is asserted for all 342 transactions in group 0;
`in_last_group` is asserted for all 342 transactions in group 447.  Tile 341
must carry mask `0x00f`; every earlier tile carries `0xfff`.  The checkers
require 153,216 accepted inputs, 448 completed input groups, 342 ordered output
tiles, 65,536 valid output elements, no sticky protocol error, and input
`II <= 1`.

## Fixed vectors and accuracy model

`model/generate_vectors.py` creates 12 fixed seeds and writes separate native
SC/FP16/FP32 scales and hardware-semantic output goldens.  The approximately
86 MiB data set includes signed and structured cases, random values, all
physical tiles, all 448 groups, the tail mask, and FP16 underflow/FTZ coverage.

`model/verify_vectors.py` checks every `.mem` file's number of rows, hex width,
shape, tail mask, and SHA-256 against `data/manifest.json`.  The manifest also
records accuracy against the common exact-scale reference.

The FP16 multiply model includes the AMD generated-IP minimum-normal underflow
threshold `tiny - smallest_subnormal/4` and three directed boundary cases.  A
plain IEEE/NumPy round followed by FTZ is not equivalent at this boundary.

### Real Llama trace and checkpoint workload

`model/generate_trace_vectors.py` builds three independent full-shape replays
for layers 0, 15, and 31.  Each layer uses 16 rows selected from the two frozen
BF16 `swiglu_down_input` tensors and the matching checkpoint
`down_proj.weight`.  The resulting `data_trace/` tree contains 3 × 153,216
group-major transactions and 3 × 65,536 valid outputs (about 257 MiB).

The activation generator uses the production fixed-point Hadamard followed by
the experiment-local raw-Min/Max A8 reference. The current 257-MiB payload in
`data_trace/` has been fully regenerated and byte-compared; the former robust
payload is preserved separately in `data_trace_robust_clipping_legacy/`, and
the pre-fix FP16 golden is preserved in
`data_trace_fp16_round_then_ftz_legacy_20260910/`. The W4
payload is generated by the production V5
artifact exporter: normalized folded group32 checkpoint weights, max-abs/7,
ScaleCode U8/shift6, round-half-away against the decoded scale, and S4 clamp.
SC and both FP baselines receive the same centered S9/W4 values and the same
decoded scale; only the scale representation/application changes.  This keeps
the M11 producer outside M12 and prevents double-counting it.

The full verifier checks trace/checkpoint/source hashes, all file geometries,
the tail mask, and then regenerates all 257 MiB into a temporary directory for
byte-for-byte comparison:

```bash
cd /home/user/EDA-202/zhuowenjun/ScaleLLM/ModularExperiment
python3 experiment/12_mlp_down_a8w4/model/verify_trace_vectors.py
```

The real layer-31 workload contains six genuine S24 output saturations at
rows 0/8 and output columns 788/1384/4062.  They are retained as negative
range evidence and must not be removed from the RTL replay.

`model/verify_fp16_correction.py` compares the frozen pre-fix and corrected
trace trees, requires that only the three FP16 expected payloads differ, checks
the exact per-layer element/tile counts, verifies the failed run's directory
hashes and proves that all 200 corrected layer-0 tiles equal the 200 RTL
mismatch tiles.  The failed run remains diagnostic and is never rewritten.

## Validation stages

The serial smoke test uses a deterministic, nonzero 5 groups × 16 tiles
workload while preserving the complete 96 pair lanes/192 output lanes.  Local
tiles 0..14 reuse the synthetic construction and local tile 15 reuses physical
tile 341, including the real `0x00f` tail.  Of the 80 transactions, 64 have a
nonzero arithmetic contribution (group 0 is the directed zero case); all 2,944
valid output elements are nonzero in each variant.  The mini vector verifier
binds all payloads, goldens, the generator and the corrected FP semantics by
SHA-256 and supports independent regeneration/byte comparison.

Each small run logs all 288 accepted 256-bit output words and functional timing
metrics.  `run_serial_ab.sh` executes a default-debug/WDB run followed by a
debug-off/custom-no-wave run, then requires output words, handshake/timing
metrics and PASS summary to be byte-identical.  It also fails closed before
launch if unrelated Vivado/XSIM is active on the shared host.  Serial A/B,
full XSIM and OOC share one nonblocking `flock`, so M12 cannot accidentally
launch overlapping hardware jobs.  The full test
then reads only the common plus selected variant's fixed vectors and checks
every completed tile against its own SC/FP16/FP32 golden.

The frozen mini workload can be checked, or intentionally regenerated and
byte-compared, without Vivado:

```bash
python3 experiment/12_mlp_down_a8w4/model/verify_mini_vectors.py
python3 experiment/12_mlp_down_a8w4/model/verify_mini_vectors.py --regenerate
```

The formal OOC top is a common 256-bit serial physical harness.  It does not
reduce the internal arithmetic or tile state: all 192 lanes and all 342 state
entries remain inside the measured hierarchy.  The narrow boundary avoids an
invalid placer comparison dominated by thousands of package I/O terminals.

Each result directory records `STATUS`, exit status, input/source hashes and
directory-level `SHA256SUMS`.  OOC validity additionally requires nonnegative
WNS/WHS, zero DRC errors, zero unrouted nets, the post-route checkpoint and all
reports.  See `result/12_mlp_down_a8w4/SUMMARY.md` for the current evidence
level; early small-geometry production regressions are diagnostic only.
