## 阻塞项

### B1 / P0：双路权重请求被切断，且存在非法输出连接

[production_core.sv:420](../../project/hardware/rtl/integration/hap_attention_mlp_production_core.sv#L420) 将 m0_arvalid 置零，427 行将 a1_arvalid 置零。现有 [paired scheduler:524](../../project/hardware/rtl/integration/hap_axi512_paired_2client_read_wrr.sv#L524) 要求同一引擎的两路描述符同时存在，才使该引擎 eligible；656/662 行由 pair_fire 推送两物理出口。当前连线使两引擎都无法形成完整 pair，任一权重命令都会等待缺失的一路。

此外，production_core 的 423–424、430–431 行把 scheduler 的 RVALID/RDATA/RRESP/RLAST 输出接到常量，不是合法的输出连接目标；相应引擎的返回线反而未驱动。单文件语法检查没有证明这些连接通过完整 elaboration。

两路并非备用端口：[Attention assembler:34](../../project/hardware/rtl/attention/hap_dual_ddr_weight_group_assembler.sv#L34) 等待两条 2048 位半组，再拼为 4096 位；[MLP join:31](../../project/hardware/rtl/mlp/hap_mlp_w4_dual_channel_join.sv#L31) 等待两条 1024 位半组，再拼为 2048 位。因此，直接绕过 scheduler 并仅保留 a0→DDR0、m1→DDR1 也无法得到完整权重。

所需修复：在各引擎专属物理 DDR 上保留全部逻辑权重流，通过经过设计的串行读取/仲裁/返回分流，或等价的单通道 reader 及地址布局完成重构。保持 format05 的有效权重、列顺序与数值规则，不可用删除半组来实现分离。

### B2 / P1：MLP 数据和 metadata 仍接 DDR0

[production_core.sv:469](../../project/hardware/rtl/integration/hap_attention_mlp_production_core.sv#L469) 的 u_data_arb 仍将 Attention DMA、MLP tensor DMA、MLP metadata DMA 合并到 data_axi。[create_vcu118_board.tcl:593](../../project/hardware/vivado/scripts/create_vcu118_board.tcl#L593) 的 Host 能访问两个 DDR，但 core_data 仅映射 DDR0（595、604 行）。

因此改变 Host 地址到 DDR1 并不会自动改变 FPGA 的读写目标。需设计 MLP 的 DDR1 数据/metadata 通路，并统一 Host 地址、通道本地偏移、CSR 与 BD 映射；验证真实 AXI 目标和读回数据。

### B3 / P0：Host 接口断裂，且权重与 KV 区重叠

[scalellm_hardware.py:11](../../project/hardware/host/scalellm_hardware.py#L11) 仍导入 ATTENTION_META_BYTES、MLP_DOWN_META_BYTES、MLP_GATE_META_BYTES、ROPE_BYTES、activation_base_for_buffer、mlp_meta_bases，但当前 scalellm_memory.py 没有这些定义。scalellm_artifacts.py:19 也依赖已删除的常量和 matrix_regions。硬件后端无法按现有导入接口加载。

当前 LayerAddresses 只有 attention_weights/mlp_weights 两个地址字段，而 hardware.py:383–384、514–517 仍访问 attention_c0/c1、mlp_gate_c0/c1、mlp_down_c0/c1。仅补回 import 名称仍不足以修复运行路径。XdmaLayerStager._write（artifacts.py:294）也仍固定写 channel 0。

[scalellm_memory.py:50](../../project/hardware/host/scalellm_memory.py#L50) 定义 32 × 20 MiB Attention 权重，范围为 [0x00000000, 0x28000000)，即 640 MiB；KV 区定义为 [0x20000000, 0x26000000)，即 512–608 MiB。**整个 96 MiB KV 区都在权重区内。** 当前 validate_address_separation 只检查各区不跨 DDR 边界，没有检查同一 DDR 内各区域相交。

本轮使用 Python 标准库 AST 静态核对缺失导出，并按上述常量计算交集；没有导入或执行 Host 模块。需要统一实际 artifact 大小、布局、加载策略和驱动接口，覆盖区域交集及完整 Host 调用链；现有地址分类单测不能替代这些检查。
