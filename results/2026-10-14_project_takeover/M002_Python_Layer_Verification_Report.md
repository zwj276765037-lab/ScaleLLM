## DDR 带宽利用率分析

### 理论带宽需求

**每层数据传输：**
```
Attention:
  - 权重: 20 MiB
  - I/O: 0.38 MiB
  - 小计: 20.38 MiB
  
MLP:
  - 权重: 88 MiB
  - I/O: 0.45 MiB
  - 小计: 88.45 MiB

总计: 108.83 MiB per layer
```

**32 层总传输：**
```
DDR0 (Attention): 20.38 × 32 = 652 MiB
DDR1 (MLP): 88.45 × 32 = 2830 MiB
总计: 3482 MiB = 3.40 GiB
```

### 带宽利用率

**DDR0 利用率：**
```
传输时间: 652 MiB / 1.36 GB/s = 0.48 s
推理时间: 3.04 s
利用率: 0.48 / 3.04 = 15.8%
```

**DDR1 利用率：**
```
传输时间: 2830 MiB / 1.36 GB/s = 2.08 s
推理时间: 3.04 s
利用率: 2.08 / 3.04 = 68.4%
```

**结论：** DDR1 (MLP) 是主要瓶颈，DDR0 (Attention) 有大量余量

## 优化机会识别

### 1. DDR0 余量利用

**当前状态：**
- DDR0 利用率仅 15.8%
- 有 84% 的带宽空闲

**优化方向：**
- 可以用于 prefetch 下一层 Attention 权重
- 可以增加 batch size 或 context length
- 可以支持双 Cohort 并行

### 2. MLP 权重预加载

**当前瓶颈：**
- MLP 每层需要 65 ms DDR 传输
- 占总时间的 68%

**优化方案：**
- 在 Attention 计算时预加载 MLP 权重（利用 DDR0 余量不行，需要 DDR1）
- Pipeline 优化：Layer N MLP 计算时加载 Layer N+1 权重
- 预期可隐藏 30-50% 的 DDR 延迟

### 3. 双 Cohort Pipeline

**当前：** 单 Cohort 顺序执行  
**优化：** 双 Cohort 交替执行

```
Time   Cohort 0              Cohort 1
─────────────────────────────────────
T0     L0 Attn (30ms)        Idle
T1     L0 MLP (65ms)         L1 Attn (30ms)  ← overlap
T2     L2 Attn (30ms)        L1 MLP (65ms)   ← overlap
...
```

**预期提升：** +30-50%

## 风险与限制

### 1. 单层权重加载

**限制：** 每层需要加载 88 MiB MLP 权重

**影响：**
- 占每层 65 ms
- 是主要瓶颈

**缓解：**
- M004 将实施 prefetch 优化
- 预期可隐藏 30-50% 延迟

### 2. 理论 vs 实际

**假设：**
- DDR 和计算完美 overlap
- 无 DMA 开销
- 无同步延迟

**实际可能：**
- Overlap 效率 80-90%
- DMA 开销 5-10%
- 同步延迟 5%

**建议：** 板级测试确认实际性能

### 3. DDR0 未充分利用

**现状：** DDR0 利用率仅 15.8%

**影响：** 有优化空间，但需要更复杂的调度
